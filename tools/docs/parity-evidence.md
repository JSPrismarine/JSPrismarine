# Parity video evidence

Parity clips are generated by the client e2e job in CI. The docs build downloads the latest supported protocol's recording and preview into `tools/docs/site/public/parity-evidence/` before assembly. A relative `.gitignore` keeps those generated media files out of commits. VitePress copies them into the docs site, so GitHub Pages serves them alongside the tracker.

To attach a recording, add its stable case `id` from the generated `parity-tracker.json` to `tools/docs/parity-evidence.json`. Keep the media filename and the docs CI artifact copy step in sync. Each case maps to one or more clips:

```json
{
    "version": 1,
    "cases": {
        "<tracker-case-id>": [
            {
                "label": "After fix",
                "src": "parity-evidence/<recording>.mp4",
                "caption": "The behavior now matches the Java Edition reference.",
                "poster": "parity-evidence/<preview>.webp"
            }
        ]
    }
}
```

The `src` path is relative to `tools/docs/site/public/`. Videos can use MP4 or WebM; optional posters can use AVIF, JPEG, PNG, or WebP. The docs assembly checks that every case ID exists and every referenced file is a local public asset. Clips load only when a reader opens the case's video evidence.
