Inventory of the gameplay behaviors a vanilla Bedrock server implements ​

Researched 2026-10-24. Scope: the set of behaviors the Bedrock engine implements for blocks, items, entities (non-AI mechanics), the world and the player, sized against vanilla 1.26.50 content so a data-driven server can track parity per behavior. This note builds on bedrock-data-extraction.md and does not repeat it. Sources, in order of authority: MicrosoftDocs/minecraft-creator at 4432fb62a8e0ce5c785bd2bf02a6f981dcffbbe8 (block, item and entity component references, block traits, Script API @minecraft/server); Mojang/bedrock-samples v1.26.50.4 at 46ba6ea985fb5a92d79a9419198f10dda14c199d (metadata/vanilladata_modules/, behavior_pack/items/); the composed vanilla behavior pack from BDS 1.26.51.1 (entities, blocks, recipes, loot, spawn rules); Java Edition's block definition types from misode/mcmeta tag 1.21.11-summary and item default components from mcmeta summary at f41a317b67b4e08155bf8b2ac3e853516d1fd889 (26.4 snapshot 5); minecraft.wiki raw wikitext as a secondary source for mechanics Mojang does not document. Every claim taken from the wiki is marked "(wiki)". Counts come from scripts kept under /tmp/bds-research-inventory/tools/ and are reproducible from the last section.

Summary ​

  • Mojang's data modules name 1463 blocks, 1623 items, 129 entities, 37 effects, 42 enchantments, 89 biomes, 25 structures, 3 dimensions, 6 cooldown categories and 47 potion effects, but no file names what any of them does. Only the Java definition.type field (263 block classes over 1166 Java blocks) and Java's item default components (62 non-cosmetic component types) enumerate behavior families publicly.
  • Sorting all 1463 Bedrock blocks by behavior gives 164 families. 188 blocks are plain full cubes with no behavior beyond their properties, 299 are slabs or stairs, 124 are Education chemistry blocks, and 72 families contain a single block. The 10 largest families cover 56 percent of blocks, the 30 largest cover 78 percent, the 50 largest cover 88 percent.
  • 912 of the 1463 blocks carry at least one block state; 157 state names exist. The 20 most used states are placement geometry (vertical_half, cardinal_direction, facing_direction, pillar_axis, corner, connection_*, wall_connection_type_*), so placement rules are the single largest block-side behavior.
  • 1623 items sort into 85 families. 1086 of them are block items, 88 are spawn eggs, 40 are plain materials with no use behavior. The 10 largest item families cover 86 percent of items; 48 families hold a single item (bow, shield, elytra, totem, each compass, each bucket kind).
  • The documented block component list (45 entries) parameterizes properties, placement filters, liquid and precipitation reactions, piston movability, redstone conductivity and production, ticking and loot, but it has no component for any interaction (open, ring, sleep, brew, compost). The Script API BlockComponentTypes enum exposes 15 engine components, and BlockCustomComponent lists the 15 hooks the engine fires (onPlace, onBreak, onNeighborChanged, onRandomTick, onTick, onNamedTick, onRedstoneUpdate, onEntityFallOn, onStepOn, onStepOff, onPlayerInteract, onBlockStateChange, and three more). Those hooks are the engine's block behavior interface.
  • The documented item component list (55 entries) covers food, durability, repair, enchantability, digger speeds, wearable slots, shooter, throwable, projectile, cooldown, fuel, record, seed, compostable, block and entity placers, bundles and the 1.26 kinetic and piercing weapons. Nothing expresses buckets, maps, compasses, clocks, shields, elytra, totems, books, banners, fishing rods, shears, flint and steel, firework rockets, spyglasses, brushes, goat horns or name tags; 34 item families need code the component model cannot name.
  • Vanilla entities use 202 non-AI component types (170 behavior.* goals excluded) out of 203 documented. Grouping them gives 26 mechanics; the ten used by the most entities are physics (126), collision box (125), type family (124), health (94), movement speed (93), breathing (84), loot (78), despawn (76), melee attack (48) and riding (36).
  • World and player mechanics number 32 in this inventory. The Script API GameRule enum names 38 rules, the vanilla player entity file parameterizes hunger (exhaustion_values, player.saturation), insomnia (3 days), breathing (15 supply, 3.75 s inhale) and death experience (Math.Min(query.player_level * 7, 100)), and the composed pack supplies 1892 recipes in 7 types, 309 loot tables using 23 functions and 16 conditions, 60 spawn rules using 21 condition components and 27 trade tables.
  • The 25 behaviors that cover the most content (section 5) account for 1215 of 1463 blocks (83 percent) and 1381 of 1623 items (85 percent). Plain full block, block item placement, slab, stairs, pillar, spawn egg and the per-state property reads come first; signs, containers, doors and gates, plants and the gravity family follow. The uncovered remainder is 124 Education blocks and 124 blocks spread over 62 small families.
  • Education Edition content (124 chemistry blocks, 36 hard glass blocks, colored torches, underwater TNT) is 11 percent of the block list, and mojang-items.json omits the matching items. The plan should decide whether it is in scope before sizing.

1. Block behavior families ​

Method ​

The 1463 names come from mojang-blocks.json (data_items[].name), the states from the same file's properties lists. Java's taxonomy comes from misode/mcmeta block_definitions/data.json at tag 1.21.11-summary (1166 blocks, 263 type values); the current summary branch (26.4 snapshot 5) and the freshly generated Java 26.3 reports/blocks.json at /tmp/bds-research-java/out/generated/reports/ no longer carry definition, so the 1.21.11 tag is the last public copy. Java types that only differ by cosmetic class (tinted_particle_leaves and untinted_particle_leaves, weathering_copper_* and waxed_*, drop_experience and plain block) collapse into one Bedrock family; Bedrock blocks with no Java counterpart (*_double_slab, *_standing_sign and *_wall_sign, cauldron with cauldron_liquid, light_block_N, element_N, camera, allow, deny, border_block, info_update is absent, moving_block is absent) get families of their own. The classifier is /tmp/bds-research-inventory/tools/block_families.py; it assigns by explicit name sets first, then suffix regexes, then falls back to "plain full block". The fallback list was read by hand; every block in it has no state other than pillar_axis, infiniburn_bit (bedrock) or cardinal_direction (pumpkin).

The "data today" column uses this legend. "props" means the per-state engine dump already pinned in packages/bedrock-data/src/resources/blocks.json (hardness, explosion resistance, friction, light emission and dampening, flame and burn odds, map color, solidity, collision geometry); it exists for every block. "shape" means a voxel shape file exists in shapes/ (218 blocks). "json" means the block is one of the 98 JSON blocks (mining seconds, explosion resistance, map color, flammability, redstone conductivity, loot table, liquid detection, instrument sound, support shape, chest obstruction, and the undocumented block_archetype). "loot" means a loot table exists; only the 98 JSON blocks have one. "recipe" and "feature" mean the composed pack has recipes producing the block or features placing it. Nothing in the data expresses interactions, state transitions or tick logic for any block.

2. Item behavior families ​

Method ​

The 1623 names come from mojang-items.json. 1101 of them share a name with a block and are block items; the classifier (/tmp/bds-research-inventory/tools/item_families.py) assigns the other 522 by explicit sets and suffix regexes, with "plain material" as the fallback for names with no use behavior. The Java cross-check maps each Bedrock name to the Java item (renames such as ender_eye, experience_bottle, frame, reeds applied) and lists the Java default components that are not cosmetic (attribute_modifiers, item_name, lore, rarity, tooltip_display, break_sound, use_effects and friends dropped). Java components are a second, independent inventory of what is parameterizable: tool, weapon, equippable, consumable, food, max_damage, repairable, enchantable, use_cooldown, use_remainder, cooking_fuel, compostable, jukebox_playable, provides_pottery_pattern, provides_banner_patterns, provides_trim_material, bucket_entity_data, entity_data, block_transformer (axes, shovels, hoes), blocks_attacks (shield), glider (elytra), death_protection (totem), kinetic_weapon and piercing_weapon (spears), charged_projectiles (crossbow), fireworks, instrument (goat horn), map_decorations, potion_contents, ominous_bottle_amplifier, writable_book_content, stored_enchantments, banner_patterns, bundle_contents, sign_text_*, dye, damage_resistant (nether star), mob_visibility, villager_food.

The Bedrock component column names the documented component that would express each part of the behavior; "none" means the item component list has nothing for it and the engine implements it by item type. Vanilla's own JSON covers only the 79 files listed in bedrock-data-extraction.md (50 foods, 17 bundles, 7 spears, seeds, trial keys, wind charge, breeze rod, camera, red shrub, shelf mushroom).

Open questions ​

  • block_archetype values seen in the 98 JSON blocks are slab_block, stair_block, bush_block and wall_foliage_block. Nothing public says whether the engine has archetypes for the other families or how many exist; the 26.50 changelog only announces the loader change.
  • sulfur_spike and potent_sulfur (1.26) have no documentation in the creator docs at this commit and no wiki page was fetched for them; their behavior is unknown here.
  • written_book, skull and tipped_arrow are missing from mojang-items.json while the game has them; whether the module omits items that only exist with NBT or aux data was not verified.
  • mojang-entities.json and the composed pack both give 129 entities; bedrock-data-extraction.md counted 130 identifiers across layers. The extra identifier was not located.
  • Copper oxidation probabilities, Bedrock's enchanting offer formula, phantom spawn weights and regional difficulty are documented only for Java or not at all; the Bedrock numbers need in-game measurement or a Script API test.
  • Whether copper chests (1.26) change behavior with oxidation, and whether copper grates block projectiles, was not verified.
  • The Java 26.3 data generator and mcmeta's current summary branch no longer emit definition.type; the 1.21.11 tag is the last public Java class taxonomy and lacks the 1.26 Bedrock additions (poplar, cinnabar, sulfur, shelves exist in Java 1.21.11 as minecraft:shelf).
  • The wiki pages used as secondary sources mix Java and Bedrock statements; every number taken from them is marked but not independently verified against BDS.
