"@jsprismarine/client": minor

Register packet handlers on the client in the shape `@jsprismarine/protocol/handler/PacketHandler` shares with the server. `ClientSession.registerHandler(PacketClass, handler)` registers a handler under the packet class's name and returns a function that removes it. The handler's `handle(payload, context)` gets the payload that class decodes and a `ClientContext` from `net/ClientHandler` (the session's `send`, `sendImmediate`, `enableCompression` and `enableEncryption`, and a logger), and it runs only in the phases its `phases` lists. The session starts in the `login` phase, and `LoginSequence` moves it to `play` once it has answered the spawn; `getPhase()` and `setPhase()` read and change it. What a handler returns is counted by `isIdle()` and `settled()` until it settles, and a handler that fails is logged as a warning. `ClientPacketRegistry` holds the handlers (`registerHandler`, `dispatch`), and a `DecodedPacket` now carries the `packet` that decoded it.

The login, the dimension change and the end credits answer through these handlers instead of listening to the session's `packet` event, so emitting `packet` on a session by hand no longer drives them. Their constructors no longer take a logger, because handlers log through their context: `new LoginSequence(session, auth, options)`, `new DimensionChange(session, runtimeEntityId)` and `new Credits(session, runtimeEntityId)`. The `packet` event stays for code that watches the packets a session reads.
