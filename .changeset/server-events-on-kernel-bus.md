The server's events move to the kernel's event bus, and the legacy `EventEmitter` is deleted. `Server` no longer extends it. `server.on`, `once`, `removeListener`, `removeAllListeners` and `hasListeners` keep their names and arguments and subscribe on `server.getKernel().events`, which is typed by the new `ServerEvents` map with the same 18 events and event classes. `server.emit`, `server.post`, `server.evtThirdParty`, `EventEmitter`, `PluginEventEmitter` and `EventTypes` are removed. A plugin that raised a server event calls `post` or `emit` on `server.getKernel().events` instead. `emit` waits for each listener, an asynchronous one included, before it calls the next, and settles once the last has finished. `post` calls every listener at once and waits for none, so what an asynchronous listener does after its first wait can run after the listeners behind it; use `emit` when a listener has to finish before the next one starts. Each event is raised where and when it was before. What a listener sees differently: listeners are called in subscription order, and the server raises `raknetConnect`, `raknetDisconnect` and `raknetEncapsulatedPacket` with `emit`, so each of their listeners waits for the one before it; a listener that throws or rejects is logged and no longer stops the listeners after it or the action that raised the event; and subscribing the same function to an event twice still calls it once. `TickerServer` takes the bus as `events` in place of `emitTick`, and the handler services' `events` is the bus.
