# @jsprismarine/java-packs

## 0.27.0

### Patch Changes

- [#3865](https://github.com/JSPrismarine/JSPrismarine/pull/3865) [`5e48c58`](https://github.com/JSPrismarine/JSPrismarine/commit/5e48c5886939f9d9ab9f520a57d0913b459eed52) Thanks [@filiphsps](https://github.com/filiphsps)! - Add `@jsprismarine/java-packs`, which converts a stack of Bedrock resource packs into one Java Edition resource pack. `convertResourcePacks` writes `pack.mcmeta` for the target release's resource pack format, the icon, every PNG and TGA texture as PNG under the `bedrock` namespace with its flipbook animation and atlas source, the language files with Bedrock's keys, the sounds that ship as Ogg Vorbis, and glyph fonts. It returns a report per pack of what converted, what a later step converts and what a vanilla Java client cannot show. `decodeTga` and `encodePng` are its image codecs.

- [#3904](https://github.com/JSPrismarine/JSPrismarine/pull/3904) [`06b614c`](https://github.com/JSPrismarine/JSPrismarine/commit/06b614cfe6dc281ff1b6b048d46789a64e594a70) Thanks [@filiphsps](https://github.com/filiphsps)! - `convertResourcePacks` takes the custom items to draw as a third argument. Each item gets an `items/` definition under its model key and a flat item model over the texture its icon names in `textures/item_texture.json`, and a texture outside `textures/items/` joins the item atlas by name. The report counts the items each pack drew and notes an icon the stack does not hold. `JAVA_PACK_CONVERTER_VERSION` is 2.

- [#3865](https://github.com/JSPrismarine/JSPrismarine/pull/3865) [`0c063d3`](https://github.com/JSPrismarine/JSPrismarine/commit/0c063d36d51d1366c82acb0ac959efea50f39ba9) Thanks [@filiphsps](https://github.com/filiphsps)! - A Bedrock pack that retextures a vanilla block or item retextures it on Java too: `convertResourcePacks` writes the texture, and its flipbook animation, over each Java texture it is, from a table matched pixel for pixel between the pinned Java client jar and Mojang's vanilla Bedrock resource pack. A vanilla Bedrock texture with no Java counterpart, such as a Bedrock-only block's, is reported. `decodePng` reads PNG files of every color type and bit depth, interlaced or not.

- [#3867](https://github.com/JSPrismarine/JSPrismarine/pull/3867) [`2003938`](https://github.com/JSPrismarine/JSPrismarine/commit/2003938841c939febb173622050377f01a630255) Thanks [@filiphsps](https://github.com/filiphsps)! - Java Edition players get the installed addons' resource packs, converted into one Java resource pack. The server converts the packs once each time they change, keeps the result in `cache/java-packs/`, serves it from its own Java port by its SHA-1, and pushes it as a client configures; `texturepack-required` makes declining it end the join. A player in play gets a new pack when the addons change, and keeps the old one until the new one loaded. The new `java-resource-pack-url` setting serves the packs from a base URL instead, and the server offers a pack there once that URL serves it. `@jsprismarine/java-packs` exports `JAVA_PACK_CONVERTER_VERSION`. `@jsprismarine/client`'s `JavaClient` downloads, checks and loads a pushed pack, or declines it with `resourcePacks: 'decline'`.
