Releases ​

Every server package ships at the same version, so one set of notes covers the server and its packages. These notes come from the server's changelog. The newest 6 of 35 releases are below; the full changelog has the rest.

v0.19.1

patch2026-11-09

Fixes and changes 3

  • A broken bed or banner now drops the item of its own color instead of the black one. Bedrock keeps their color in the block entity, so the loot lookup reads it from there: blockEntityRecord exposes a bed's color and a banner's Base as dyeIndex, blockLootTableOf and rollBlockDrops use it to pick the Java table, and /loot mine passes it too. @jsprismarine/mapping adds bedrockBlockEntityDyeIndexOf and javaBlockOfBedrockDyeIndex to convert between a Java colored block and that index.

    5129bc5

  • ChunkScheduler.tick no longer spins when every player's next chunk has to wait for generation depth. A deferred chunk reset the count of players with nothing to send, so two or more players behind a full depth kept the pass going until the 5 ms budget ran out, every tick. With an injected clock that never advanced, it never ended at all. This happened on two-core hosts, where the default depth is two. A full round of deferrals now ends the pass, and a chunk held for a sender without enqueue returns to the front of its queue.

    52d1d18

  • SharedTerrainTileStore no longer blocks a worker thread while it waits for another owner to finish building a terrain tile. It waited with Atomics.wait everywhere but the main thread, which held the whole thread, so an owner running on that thread could not finish until the 100 ms timeout passed. Both waits now use Atomics.waitAsync, and releasing a slot also wakes a waiter on its initialization word.

    e3adf62

v0.19.0

minor2026-11-09

New 2

  • DataEntity.equipmentInventorySlots is now a Map<MobEquipmentSlot, number> instead of a partial record. Read a slot with get, set one with set and clear one with delete. Saved entities keep the same on-disk shape. The new withoutEquipmentSlot helper in entity/equipment copies an equipment set with one slot emptied.

    6b28547

  • Player.setPosition now takes the same options as Entity.setPosition, the new exported EntityPositionOptions. The movement mode and the broadcast flag moved to Player.setPlayerPosition(options, broadcast), so replace player.setPosition({ position, type }, false) with player.setPlayerPosition({ position, type }, false).

    fb2dffc

Fixes and changes 14

  • BaseProvider now declares the optional members of Provider, such as supportsChunkUnload, readPlayerData and the replay snapshot methods. Level, World and the test level helpers type their provider as BaseProvider instead of BaseProvider & Provider.

    84bb6e0

  • The block pass of a generated chunk's Bedrock translation now runs in a generation worker. The server thread translates each palette entry, a few dozen per chunk, and the worker walks the chunk's blocks into section indices and palettes, which was the largest part of a completed chunk's server-thread work. Chunks are byte-identical to the ones built on the server thread.

    8e09026

  • A dimension change now holds its first chunks back until the client reports that the change's loading screen opened, or for two seconds at most. A client that decoded those chunks before switching dimension filed them under the dimension it was leaving and then waited on its loading screen forever.

    11e6795

  • A dimension change for a dead player, such as a /teleport into another dimension under the death screen, now waits until the player respawns and then carries the player there. It used to go out to a client that never opened its loading screen, and every later change of world waited behind it for a minute.

    5d9abed

  • A command run in a dimension nobody has entered yet, such as execute in minecraft:the_nether run fill, no longer acts on the Overworld instead. The dimension's world is started and the command sees it with no chunks loaded, so a block write there places nothing, as Java's "That position is not loaded" does.

    e79d383

  • Point the Discord link in each package README at the project's current invite.

    e785c39

v0.18.0

minor2026-11-08

New 1

  • Village raids run. A player with Bad Omen who stands in a village starts one: the omen is spent, a countdown runs, and Java's waves of pillagers, vindicators, evokers, witches and ravagers spawn around the village, three, five or seven by difficulty and one more for a stronger omen, each only once the last is dead. Clearing every wave wins the raid and gives the players nearby Hero of the Village; a village that stops being one, a raid that outlasts 48000 ticks or one nobody is near ends it. Villagers read the raid state, so they take cover between waves and celebrate a win, and an active raid is saved with the level and carries on after a restart.

    ccf5f0b

Fixes and changes 22

  • A checkout without the Bedrock vanilla behavior pack no longer runs silently without mobs. pnpm dev now downloads the pack when the cache lacks it, and the server logs a warning that names the consequence when the pack is missing. Before, a fresh clone or git worktree started with one entity type: nothing spawned, /summon answered "Unable to summon entity" for every type, and the End had no ender dragon.

    2f242cd

  • Mob pathfinding reads blocks faster. Each block read checked its chunk's revision by summing every section's write counts, and looked up its world by scanning the level's worlds. A chunk now reuses its revision until a block is written, and a level remembers its ready worlds by dimension type. In a CPU profile of a server with eight players and their mobs, tick-loop busy time fell from about 84% to about 53%.

    b1e7419

  • Generating terrain no longer stalls the tick loop. Each terrain chunk hashed the pipeline's whole dimension and noise settings to build its cache key on the main thread; those inputs are now written once per pipeline, and the key stays identical so existing caches still hit. The cache also stopped listing and statting every record on each write. Per-tick bookkeeping got cheaper too: lighting and portal checks skip work when nothing changed, random-tick section lists skip their revision sum when no block was written, and entities without status effects skip that pass. In a CPU profile of a fresh world with eight walking bots, main-thread busy time over a 45 second window fell from about 41 seconds to about 12 seconds.

    df11bd2

  • The console follows a server's own tick rate. The status message carries an optional tickRate, and the server sends it, so a rate set with /tick rate reaches the console. The console caps TPS at that rate instead of 20, colors TPS and tick time against it, and draws the TPS page's graph up to the highest rate in the chosen span, so a span that includes a rate change shows the higher one. A console that gets no tickRate assumes 20.

    9e700bc

  • Settle the change of world after the End credits with the respawn exchange instead of a loading screen the client never closes. The client stayed on its loading screen for the server's one minute timeout, which left the next dimension change refused and the player waiting for chunks.

    7ebbc42

  • The dragon fight's "no loaded pack declares minecraft:ender_dragon" report now names the usual cause, a missing Bedrock vanilla behavior pack, and the command that downloads it.

    7c3ef46

Plus 3 dependency updates.

v0.17.0

minor

New 4

  • Load Java's block_transformer registry and resolve tool transforms from it, which is what makes a hoe till, a shovel path, and an axe strip. The behaviors and the item components were already in place, but the table behind WorldActions.transform was an injection point nothing injected, so every tool declined every block. @jsprismarine/packs routes data/<namespace>/block_transformer/ files, the server parses them into ServerContent.blockTransformers, and the resolver answers the rule-based providers over the real tag stack and block mapping, including copy_properties (a stripped log keeps its axis), the offset predicates (tilling needs air above), and disallowed_faces - which is why transform now takes the clicked face.

    8cc701d

  • Remove CommonJS package outputs

    9061024

  • Spawn mobs on the ground under leaves and plants instead of on top of them. The surface spawn pass tries one position per column, and the world adapter answered with one above the highest block that is not air: the canopy over a forest and the tall grass standing on a plain. Every passive spawn rule names the ground it belongs on, so those columns rejected every rule and most of an overworld spawned nothing. ContentBlockAccess.surfaceY now walks down to the first block that blocks motion and is not leaves, which is Java's MOTION_BLOCKING_NO_LEAVES heightmap and the one its SpawnPlacements reads. WorldContentBiomes is now WorldContentFacts and carries the block types, their flattened columns and the tag stack that the walk reads.

    541e593

  • Route sniffer seed drops, warden sonic boom damage and knockback, and villager raid effects through host capabilities.

    15dc167

Fixes and changes 131

  • Verify the Minecraft services token and the client data signature before trusting a login when online-mode is on. The account now comes only from the signed token, a login that cannot be verified is refused, and an existing session is replaced only after the new login is accepted.

    43ecda5

  • Encrypt RakNet sessions with the Bedrock handshake: the server sends ServerToClientHandshake to a login that names an identity key, and finishes the login once the client answers encrypted.

    bbc5ab9

  • Save a trader's offers, their uses and demand, and its experience with the entity, so a villager keeps them across a restart instead of drawing new ones. A damaged saved state is ignored.

    73efe0d

  • Villagers trade with players: the trade screen opens on a villager, shows its offers with their live prices, and a trade spends the payment, hands over the result and moves the villager's stock, demand, experience and level. A villager that works at its job site restocks, up to twice a day. Villagers also work with the world: farmers bake bread, compost seeds, harvest, sow and bone-meal crops, villagers share food, thank a hero of the village and have children, and a villager takes its profession and job site from its trade table. A villager remembers the player who cured it and charges that player less, and holds up its trades to a player who talks to it.

    0e4b2a8

  • Make /damage follow Java 26.3: no source entity unless by names one, from for an indirect cause, at for a location, a single target, and the damage type read from the loaded datapacks, whose tags decide what the blow bypasses.

    d84076a

  • Store section palette indices in bytes until a section needs a 257th state.

    169eec3

v0.16.0

minor2026-10-31

New 180

  • Move the painting spawn packet and its typed payload into the protocol package.

    30c3b75

  • Put the advancement engine and the enchantment system into play. Both packages were built at startup and then referenced nowhere: no gameplay code raised a single trigger, and nothing read an enchantment's effect components, so no player could earn an advancement and no enchantment did anything.

    An item stack carries its minecraft:enchantments and surfaces it through getEnchantments, getEnchantmentLevel and a copying withEnchantments; asPredicateStack hands that component to the loot, predicate and enchantment grammars along with the enchantability and durability pair the enchanting table and the anvil read. Item.hasEnchantment takes a Java enchantment id rather than ItemEnchantmentType, whose numbering covers 37 of the 43 enchantments and gives Thorns and Efficiency the same number.

    Damage reduction reads the real minecraft:damage_protection components of what is worn, one running total per equipment slot as Java accumulates it, instead of a factor that was a literal zero on every entity. Each enchantment decides for itself which blows it answers through the damage_source_properties condition in its own file, so Damage.BYPASSES_ENCHANTMENTS is empty: Java's #minecraft:bypasses_enchantments holds only a warden's sonic boom. A melee swing reads the attacker's main hand for minecraft:damage and minecraft:knockback, and Block.getBreakTime divides by the tool's mining speed, which carries minecraft:mining_efficiency.

    Fifteen of the 58 advancement triggers fire from the place that knows the event, led by inventory_changed, which 1914 of the 4045 vanilla criteria use and which is how a block break is reported, since Java has no block-break trigger. Progress rides in the player data record. The engine is built with the item and enchantment views its conditions need, and both Java grammars now parse against a reference resolver, without which a #tag inside a criterion expands to nothing.

    The enchanting table and the anvil are reachable: Java's draw behind a per-player enchantment seed that persists, Java's bookshelf walk rather than a radius count, and real options sent as a PlayerEnchantOptionsPacket instead of letting the client's own preview guess.

    The content build also passed the item tags where EnchantmentRegistry expects the enchantment tags, and nothing where it expects the item tags, which left in_enchanting_table empty and supports false for all 43 enchantments.

    87df04b

  • Move diagnostics and telemetry packet codecs into Protocol.

    94378af

  • Move the animate entity packet codec into the protocol package.

    d4d0080

  • Remove Prismarine's chunk radius packet wrappers and use Protocol's typed request and response packets.

    5733593

  • Route /summon through declared data-driven types only.

    76a3b06

Fixes and changes 340

  • Use each entity's navigation and physics data, and place spawned mobs at their correct feet positions.

    35dc8ab

  • Apply Java fluid movement to data-driven entities

    7c0cefd

  • Use loaded crafting recipes for minecraft:shareables rules with craft_into when entities share items.

    3f0e622

  • Add Anvil.regionDirectory(dimension), which answers dimensions/<namespace>/<path>/region for every dimension but the Overworld and falls back to DIM-1 and DIM1 for saves written before Java 26.1, and Anvil.listChunks(dimension), which reads the location table of each region file there.

    18d21b4

  • Fix armor granting no protection. Reading an item's armor points and toughness matched the attribute modifier id minecraft:base_armor, which no item carries. Java names the armor modifier after the slot it fills, so an iron chestplate publishes minecraft:armor.chestplate and the lookup found nothing for all 41 armor items. A full diamond set absorbed exactly as much as bare skin.

    Attribute lookups now match on the attribute type alone and sum every add_value modifier of it, so a future rename of Java's modifier ids cannot silently zero a stat again. Attack damage and durability were already correct and are unchanged.

    5f6dbf9

  • Report every protocol version the server speaks, not just the newest

    The startup banner and /version named one Minecraft version and one protocol while the server registers a codec per protocol version and negotiates per session, so a player on the older of two supported versions saw a banner that said the server did not speak their protocol. Both now list each registered protocol with its Minecraft versions, newest first, and mark the one the MOTD advertises. The refusal log names every protocol the server speaks instead of only the newest.

    The codec registry grew registeredCodecs, newest protocol version first, and describeSupportedProtocols(), which both diagnostics read, so a new codec appears in them without a second list to maintain. The MOTD still advertises only the newest version, matching Bedrock Dedicated Server.

    8d32d62
