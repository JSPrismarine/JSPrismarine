JSPrismarine / @jsprismarine/kernel

@jsprismarine/kernel ​

The module kernel from the server re-architecture plan. It owns three things: module lifecycle, a token-keyed service registry, and the event bus. Worlds, sessions, commands, networking, and the tick loop are modules; first-party and third-party modules use the same API.

A module declares the service tokens it depends on, provides its own services during register(), and does its I/O in start(). The kernel validates the dependency graph, starts modules in dependency order, and stops them in reverse. A module can only use() tokens it declared, so the declared list is the real dependency graph, not documentation.

A kernel is built once and restarted freely: registerAll() runs every register() phase exactly once (and get() resolves provided services from then on), start() runs it first when needed and then runs the start phases, and stop() returns the kernel to the registered state so start() may run again. Module services carry over across restarts; listeners a module needs after a restart belong in start(), since the bus detaches a module's listeners when it stops.

typescript
import { createToken, Kernel } from '@jsprismarine/kernel';

const bans = createToken<BanService>('prismarine:bans');

const banModule = {
    id: 'prismarine:ban-module',
    register(ctx) {
        ctx.provide(bans, createBanService(ctx.config));
    }
} satisfies Module<BanConfig>;

const kernel = new Kernel({ config: { 'prismarine:ban-module': banConfig } });
kernel.register(banModule);
await kernel.start();
kernel.get(bans);
await kernel.stop();

Event listeners registered through a module's context are tagged with the module id and detached when that module stops. The bus is a minimal typed async emitter; prismarine's EventEmitter is adapted to it in a later phase.

Testing a module ​

@jsprismarine/kernel/testing starts one module against a kernel containing only its declared dependencies, each backed by a stub the test supplies:

typescript
import { startTestModule, stubService } from '@jsprismarine/kernel/testing';

const handle = await startTestModule(banModule, {
    stubs: [stubService(storage, inMemoryStorage())],
    config: banConfig
});

A stub for a token the module no longer declares fails, as does a declared dependency without a stub and any use() of an undeclared token, so the dependency list cannot drift from what the module actually uses.

Kernel ​

Defined in: packages/kernel/src/kernel.ts:51

The module kernel. It owns lifecycle, a token-keyed service registry, and the event bus; everything else — worlds, sessions, commands, networking, the tick loop — is a module.

Lifecycle: construct the kernel once, register() modules, then drive it through registerAll(), start(), and stop(). registerAll() runs every module's register() phase exactly once and validates providers and the dependency graph; after it, get() resolves provided services. start() runs registerAll() first when it has not run, then runs the start() phases in dependency order. stop() runs stop() phases in reverse order, logging failures instead of throwing, and returns the kernel to the registered state, so the same kernel — and the services its modules constructed — can be started again. Event listeners a module attaches are detached when it stops; a module that must survive a restart attaches its listeners in start(), not register().

stop(): Promise<void>

Defined in: packages/kernel/src/kernel.ts:144

Runs stop() phases in reverse start order and detaches each module's event listeners. Failures are logged, not thrown, so one module cannot block the others' teardown. Leaves the kernel registered, so start() may run it again; a no-op unless the kernel is started.
