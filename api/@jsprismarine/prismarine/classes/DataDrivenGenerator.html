Class: DataDrivenGenerator ​

Defined in: prismarine/src/world/generators/datadriven/DataDrivenGenerator.ts:809

The chunk generator that reads Java's data.

One instance covers one server. Its own Generator methods fill the dimension the options name, and DataDrivenGenerator.forStem returns a Generator for any other stem that shares this instance's registries, caches and worker pool. Everything that depends on a PipelineKey and a seed is compiled once per pair and kept, plus recent terrain tiles shared by neighboring feature regions.

buildFullTile() ​

buildFullTile(cx, cz, seed, key?, structureStartPlans?): Promise<GenerationRegionTransfer>

Defined in: prismarine/src/world/generators/datadriven/DataDrivenGenerator.ts:1434

One finished chunk's merged region, packed for the thread that asked for it.

What a worker runs when the whole ladder is pooled. It climbs to full exactly as the main thread would and stops one step short of the Bedrock translation, which stays on the thread that holds the mapping tables.

The region is copied rather than moved. Moving it would leave this worker's holder with a detached chunk, and a second request for the same position - two worlds on one seed, a chunk the main thread let go of - would find nothing there. A copy is about 60 microseconds against a chunk that costs a couple of hundred milliseconds to build.

forStem() ​

forStem(stem): Generator

Defined in: prismarine/src/world/generators/datadriven/DataDrivenGenerator.ts:1325

A Generator for one stem over this instance's registries, caches and worker pool.

This is how three dimensions share one pool of workers: each gets a view that tags its tasks with its key, and the pipelines the key compiles are kept here, one per seed. The view's stopGenerating stops this whole generator, because a shutdown is the only caller and it is stopping the server's one pool.

locate() ​

locate(request): StructureSearchResult | undefined

Defined in: prismarine/src/world/generators/datadriven/DataDrivenGenerator.ts:1664

The nearest structure a search accepts, without generating anything.

This is what /locate asks. A structure's position is a function of the seed and the placement grid alone, so the answer comes from laying candidates out against the bare noise terrain: no chunk is built, nothing is written, and a search over thousands of blocks costs a few hundred layout attempts rather than thousands of chunks.

Synchronous, like Generator.surfaceAt and for the same reason: the command layer that asks is synchronous, and the work is arithmetic rather than a chunk.

Optional, because a generator that places no structures has nothing to find.

raiseUrgency() ​

raiseUrgency(cx, cz, urgency): void

Defined in: prismarine/src/world/generators/datadriven/DataDrivenGenerator.ts:2312

Says that a chunk already asked for is wanted more than it was.

A chunk is requested once and waited on by everybody who wants it, so the band it was given is whoever asked first. A rim chunk queued as idle is the chunk a player is standing on a moment later, and nothing else would move it up.

Only affects a request still waiting for a worker. One already being built finishes at the speed it was going to finish at either way.

Optional, because a generator with no queue has no turn to move.

stopGenerating(): void

Defined in: prismarine/src/world/generators/datadriven/DataDrivenGenerator.ts:1526

Gives up every chunk request that has not started yet, for a server that is shutting down.

A generator that answers one request at a time holds a queue, and a start region fills that queue thirty-two chunks at a time. Waiting for it to drain means a shutdown spends seconds generating terrain that the save it is about to run will not even look at. The request that is already running finishes, so no half-generated chunk is handed back; everything behind it rejects with GenerationStopped.

Optional, because a generator that answers immediately has no queue to give up.

surfaceAt() ​

surfaceAt(x, z, seed?): SurfaceProbe

Defined in: prismarine/src/world/generators/datadriven/DataDrivenGenerator.ts:1727

The topmost block of one column, without generating the chunk it is in.

The answer comes from the bare terrain: no surface rule has run and nothing has decorated, so a flooded column reads as water and a wooded one reads as the ground under the trees rather than as a canopy. That is Java's ChunkGenerator.getBaseHeight, and it is what a spawn search wants - whether a player can stand here is a question about the land, and answering it by generating a finished chunk costs four orders of magnitude more.

Optional, because a generator with no cheaper answer than its own chunks has nothing to add here and a caller falls back to generating one.
