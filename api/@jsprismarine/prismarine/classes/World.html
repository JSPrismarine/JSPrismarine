ITEM_ENTITY_LIMIT ​

readonly static ITEM_ENTITY_LIMIT: 2048 = 2048

Defined in: prismarine/src/world/World.ts:2708

The most dropped stacks one world keeps on the ground at once.

Neither edition publishes a number like this, and neither needs one. Java bounds its item entities with a 6000-tick despawn, and both editions merge stacks that land together, which this server does too in entity/other/Item.ts. What neither bounds is a burst. BlockUpdateScheduler lets one tick process 4096 positions, every one of which can destroy a block and roll its loot table, and a world that has just generated hundreds of chunks has that much work waiting in it. The reported crash was over 10,000 stacks on the ground, each one falling, comparing itself against its neighbors to merge, and going out to every player in range, every tick.

The number is this server's own judgement rather than anything Mojang publishes: well past what play produces, well short of what the per-tick merge pass can carry.

breakBlock() ​

breakBlock(position, player?): Promise<boolean>

Defined in: prismarine/src/world/World.ts:2130

Destroys the block at a position: takes it out of the world, tells every player, and plays the break where it stood.

Deliberately idempotent - a position already holding air is left alone and reported as false. Which packet announces a break depends on the breaking mode and the game mode. With server-authoritative block breaking, the default, survival reports a PREDICT_DESTROY_BLOCK in the tick's PlayerAuthInputPacket. With the client timing breaks, survival sends an InventoryTransaction, on its own or inside the input. Creative sends a PlayerAction in either mode, and a client is free to send more than one. Rather than guess which one to trust, every route calls this, and whichever arrives second finds the work already done. That is what keeps the break from sounding twice.

isRainingAt() ​

isRainingAt(x, y, z): boolean

Defined in: prismarine/src/world/World.ts:2490

Whether rain is falling on one position, Java's Level.isRainingAt.

Three of Java's four conditions: it has to be raining, the position has to see the sky, and nothing may stand above it. The fourth is the biome's precipitation, which is a temperature curve over the height that neither edition publishes in a form this repository holds, so every biome counts as rainy here and fire in a snowy one is put out where Java would leave it burning.

The sky test is the light engine's. Full sky light means an unobstructed column: sky light loses at least one per step the moment it has to travel sideways, so 15 at a position and nowhere short of the sky above it are the same statement. The engine already keeps it per block and updates it with every write, which is the whole reason not to walk the column here - World.topOfColumn answers per chunk at sub chunk resolution, so one block on a hilltop would shelter the whole chunk from the rain.

It is also Java's own test rather than an approximation of it. Level.canSeeSky reads the MOTION_BLOCKING heightmap, which a fire does not raise because it has no collision; a fire does not dampen light here either, so the position it stands in still reads 15.

updateBlockCracking() ​

updateBlockCracking(mining): Promise<boolean>

Defined in: prismarine/src/world/World.ts:1711

One tick of mining: the particles off the face being mined, then the crack progress.

A Bedrock Dedicated Server sends this pair every tick for as long as a block is being mined. The particles leave from the block's center and carry its runtime id, which the client textures them with. The progress goes to the block's corner, like the start and the stop.

The block can change while it is mined: another player breaks it, or a command or a flood replaces it. The cracks belonged to the block that was there, so they stop with it.

Parameters ​

mining ​

BlockMining

What is being mined.

Returns ​

Promise<boolean>

False when the block is no longer the one being mined, in which case its cracks were stopped and nothing else was sent.

disable() ​

disable(): Promise<void>

Defined in: prismarine/src/world/World.ts:802

On disable hook.

The order is the whole of it. Marking the world closing stops the preload asking for more chunks and stops the tick; waiting for the start region means every chunk that was generated is in this.chunks before the save walks it; and the provider is closed last, once nothing is left that could ask it for anything.

An autosave a tick started is one of those things. World.save waits for it before writing anything of its own, so by the time the level closes the provider no write is outstanding - closing the database under one is the same failure the start region race used to cause. The provider itself is the level's to close, once every world of the save has been through this.
