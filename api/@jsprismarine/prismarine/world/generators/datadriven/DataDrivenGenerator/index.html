biomeSource? ​

readonly optional biomeSource?: BiomeSourceDefinition

Defined in: prismarine/src/world/generators/datadriven/DataDrivenGenerator.ts:180

The biome layout of the default key, as the biome_source of a level stem describes it.

A definition rather than a built BiomeSource, because the worker threads build their own generator and an object with closures cannot cross a thread. A multi_noise preset resolves through the reports/biome_parameters registry. Defaults to the minecraft:overworld preset.

chunks? ​

readonly optional chunks?: ChunkPoolOptions

Defined in: prismarine/src/world/generators/datadriven/DataDrivenGenerator.ts:261

Where to run whole chunks, and how many at a time.

Absent by default, which builds them on this thread. This is the pool that pays: a terrain pool leaves the decoration pass and the structure layout here, which is 168 of the 239 milliseconds a chunk costs, so no worker count takes it past 1.33 times. A pool of whole chunks makes all but the Bedrock translation parallel.

Pool options are alternatives, not layers. DataDrivenGeneratorOptions.stages takes precedence when supplied; otherwise this option takes precedence over DataDrivenGeneratorOptions.terrain, because a worker running the whole ladder runs its own terrain inside it.

stages? ​

readonly optional stages?: StagePoolOptions

Defined in: prismarine/src/world/generators/datadriven/DataDrivenGenerator.ts:247

Where pure terrain and features status bodies run, sharing one holder map on this thread. A worker receives the terrain tiles it reads and returns only its feature patches.

Use this when requests overlap: unlike DataDrivenGeneratorOptions.chunks, this keeps shared neighborhood work in one scheduler instead of rebuilding it in worker-local schedulers. It takes precedence over DataDrivenGeneratorOptions.chunks and DataDrivenGeneratorOptions.terrain when more than one pool option is supplied.

terrain? ​

readonly optional terrain?: TerrainPoolOptions

Defined in: prismarine/src/world/generators/datadriven/DataDrivenGenerator.ts:237

Where to run the terrain bodies, and how many at a time.

Absent by default, which runs them on this thread. A pool is worth about 4.7 times one thread at five or six workers on an Apple M1 Pro, and less past that, because six of its eight cores are performance cores and a worker is a whole V8 isolate.

Only terrain goes to a worker. It writes radius 0, its own chunk and nothing else, so two of them can never touch the same block. Use DataDrivenGeneratorOptions.stages to move features as well.

PipelineDimension ​

Defined in: prismarine/src/world/generators/datadriven/DataDrivenGenerator.ts:417

The dimension as a chunk task carries it: the bounds every chunk takes and the two ids the pool and the cache key read.

A DimensionType also holds its Java definition, attributes map included, and a task is structured-cloned into a worker per chunk, so the key carries this record instead. pipelineDimensionOf makes one from a type.

PipelineKey ​

Defined in: prismarine/src/world/generators/datadriven/DataDrivenGenerator.ts:445

What picks one compiled pipeline out of a generator shared between dimensions: the settings a level stem names and the dimension it fills. The seed is the other half of the cache key and travels separately, because one key serves every world on the server that uses that stem.

Plain data, because every task carries its key across the worker boundary and the worker compiles the pipeline from it. One generator and one worker pool therefore serve the Overworld, the Nether and the End instead of three of each.
