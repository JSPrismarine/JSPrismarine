JSPrismarine / @jsprismarine/console-protocol

@jsprismarine/console-protocol ​

Message types and links between the JSPrismarine server and its console.

When the server runs under the terminal UI it is a child process, and the two sides talk over Node's IPC channel. This package defines what they say to each other and how a message gets from one side to the other. It depends only on @jsprismarine/logger (for LogLevel), so neither the server nor the host pulls in a renderer by importing it.

There are three message families. ServerMessage is everything the server sends: hello on connect, log records with a sequence number and log.dropped when the server had to shed records, status with TPS, player count, memory, and uptime, lifecycle state changes, and command.result and complete.result replies. ConsoleMessage is what the console sends back: command, complete, subscribe to set the log level, and shutdown. SupervisorEvent never crosses the channel; the host raises it for the UI to describe its own state (watching, a changed path, regenerating data, a restart, raw child output).

A MessageLink<In, Out> is the channel itself: send, onMessage, onClose, close. send returns false when the channel asks the sender to slow down. Three adapters implement it: childProcessLink() on the server side over process.send, subprocessLink(child) on the host side over the spawned child, and memoryLinkPair() for tests. isServerMessage and isConsoleMessage check that incoming JSON has one of the known shapes before you trust it.

Functions ​

childProcessLink() ​

childProcessLink<In, Out>(options): ChildProcessLink<In, Out>

Defined in: childProcessLink.ts:50

Builds the server-side link over the IPC channel Node opens when the host forks the server with an 'ipc' stdio entry. Messages travel through process.send in Node's JSON mode, so they must be plain JSON values. Registering a message listener makes the channel keep the process alive until it disconnects.

send returns what process.send returns: false once the unsent backlog passes Node's threshold or after the channel closed. The close listeners run when the channel disconnects, whether through MessageLink.close or because the host went away. A channel that is already disconnected when the link is built, because the host went away during startup, is reported the same way: the close listeners run on the next microtask, which leaves the caller its synchronous turn to register them, so the server still learns to shut down.

subprocessLink() ​

subprocessLink<In, Out>(child, options): MessageLink<In, Out>

Defined in: subprocessLink.ts:22

Builds the host-side link to a server child spawned with an 'ipc' stdio entry. Messages travel through child.send, and incoming ones pass options.validate before any listener sees them, so a stray JSON value from the child is dropped rather than thrown.

The link closes when the child's 'close' or 'exit' event fires or its channel disconnects. 'close' is needed on its own: a spawn that fails (ENOENT, EAGAIN, EMFILE) emits 'error' and 'close' but never 'exit'. stopped versus crashed is for the caller to derive from the child's exit code. MessageLink.close disconnects the channel but leaves the child running; stopping it is the supervisor's job.
