JSPrismarine / @jsprismarine/protocol / CraftingDataPacket

Class: CraftingDataPacket ​

Defined in: protocol/src/packet/CraftingDataPacket.ts:345

Every recipe the client is allowed to know about.

Sent once, on join, and identical for every player, so the encoded form is worth keeping.

Wire order at protocol 2193 is eleven arrays and a flag, each array a varuint count followed by its entries: Shaped Recipes, Shapeless Recipes, Multi Recipes, User Data Shapeless Recipes, Shapeless Chemistry Recipes, Shaped Chemistry Recipes, Smithing Transform Recipes, Smithing Trim Recipes, Potion Mixes, Container Mixes, Material Reducers, then Clear Recipes as a boolean. There is no type id in front of a recipe: its list is its type.

Four of the eleven have no payload type here and are written empty. Written empty rather than left out: absent, they do not save four bytes, they misalign everything after them. Cooking recipes have no list at all at this version, because smelting became client-side data; a server still smelts with its own recipes, it just no longer says so here.

An ingredient is a RecipeIngredient, which is the legacy descriptor form and not the recipe-ingredient type page's. A result is an ItemStack.

getWriteBuffer() ​

getWriteBuffer(): Buffer

Defined in: binaryutils/src/BinaryStream.ts:894

Returns the encoded bytes as a view over this stream's internal buffer.

The view is only valid until the next write: resetWrite, clear and reuse all rewind the cursor without reallocating, so a previously returned buffer is silently overwritten by the next packet. If you queue the result - a send queue, a resend window - use copyOut or copyInto instead.

It also keeps the whole pooled 64 KB chunk it was carved from alive; retaining a scattered handful of small packets this way can pin megabytes.

reserve() ​

reserve(capacity): this

Defined in: binaryutils/src/BinaryStream.ts:763

Grows the write buffer so that at least capacity bytes can be written without any further allocation, and returns this stream.

Pre-sizing skips the 256 -> 512 -> 1024 ... growth ladder, each step of which copies the whole payload; a 3 KB packet starting from the 256-byte floor performs five allocations and memcpy's 1.25x its own size before it is done.

resetWrite() ​

resetWrite(): void

Defined in: binaryutils/src/BinaryStream.ts:785

Rewinds the write cursor while keeping the allocated capacity, so a long-lived encoder reaches a steady state where it never allocates again. This is the intended way to reuse a stream for many packets.

Note the aliasing contract, which it shares with clear and reuse: any buffer previously handed out by getWriteBuffer is a view over this stream's memory and is invalidated by this call. Use copyOut or copyInto for output you intend to keep.
