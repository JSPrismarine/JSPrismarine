persistentNbt ​

persistentNbt: NBTTagCompound | null = null

Defined in: prismarine/src/entity/Entity.ts:178

Everything the world file said about this entity that the server does not model.

Vanilla actor NBT carries a definitions list naming the behavior pack component groups the entity was built from, along with its attributes, tags and variant. An actor written back without them spawns broken or despawns on sight, so the remainder is kept here and written out again by EntitySerializer. Null for an entity that was never read from disk.

applyKnockback() ​

applyKnockback(_directionX, _directionZ, _strength, _damping?): void

Defined in: prismarine/src/entity/Entity.ts:973

Shove this entity away from whatever hit it.

A no-op here, because the base entity has no velocity to shove. The two things that do override it, and they could hardly differ more: the body of a data-driven entity hands the impulse to the entity behind it and lets the runtime carry it, while a Player has to be asked - a player's position comes from their own client, so a server that moved them would be overruled on the next movement packet and read as rubber-banding.

claimUpdate() ​

claimUpdate(tick): boolean

Defined in: prismarine/src/entity/Entity.ts:613

Claims this entity's one update of a server tick for the world asking.

The level ticks its worlds one after another, and a portal trip moves an entity from the world being ticked into one that is ticked later in the same pass. That world finds the arrival in its roster and would update it a second time. The first world claims the tick before updating; the second sees the claim and leaves the entity for the next tick.

damage() ​

damage(amount, source?): Promise<boolean>

Defined in: prismarine/src/entity/Entity.ts:828

Hurt the entity.

The whole pipeline, in vanilla's order: grace period, then the cancellable event, then armor and its enchantments, then resistance, then absorption, and only what is left of all that comes off the health.

Takes a bare DamageCause as readily as a full DamageSource, which is what let the attacker be threaded through without touching any of the call sites - falling, drowning and starving never had one and still do not need one.

Parameters ​

number

Returns ​

touchPortal() ​

touchPortal(at, portal?): void

Defined in: prismarine/src/entity/Entity.ts:638

Records that this entity overlaps a portal block on the current tick.

The world calls this once per tick for each entity whose box overlaps a portal. The first call opens the contact; later calls refresh it. A touch while on cooldown opens nothing and winds the cooldown back to its full length instead, as Java's Entity.setAsInsidePortal does, so an entity that has just arrived only travels again after it has left the portal for the whole cooldown and stepped back in.

Vector3
