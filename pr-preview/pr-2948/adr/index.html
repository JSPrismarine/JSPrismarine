Decisions ​

  • Which edition decides an entity stat

    Bedrock's entity definitions and Java Edition's attribute suppliers publish 438 of the same stats for the same entity, and they disagree on 151 of them.

  • Generate a chunk through a status ladder, not a 3 by 3 region

    DataDrivenGenerator.generateChunk builds a 3 by 3 region, generates terrain for nine chunks, decorates the center, extracts one chunk and serializes the whole body behind one promise, at 1572 ms per chunk.

  • Describe a packet's wire layout as data, once, in the protocol package

    A packet whose layout changed at a protocol version is today a sibling class: AnimatePacket2225 extends AnimatePacket, overriding encodePayload/decodePayload, substituted per session by prepareOutbound with an Object.assign copy.

  • Describe a dimension as a Java level stem, and keep one World per dimension

    Every world this server loads is the Overworld.

  • Run chunk generation in a host process, and keep the in-process pool as the fallback

    Generation workers are threads of the server process.

  • The simulation replays identically at any host speed

    Given an initial-state manifest, the random state and an ordered inbound packet trace, a replay produces the same per-tick replay digest series and the same outbound packet digests on every run, however fast the host is.

  • One entity index, and a position write is visible to the next query

    The world kept two entity indexes with opposite rules.

  • One entity model, with players and items in the same store

    Every entity in a world lives in one entity store, and every entity has the shape a data-driven mob has today: a reference to a resolved entity type, the component state of an EntityInstance, and a body.

  • External inputs enter a world once per tick and are recorded

    Anything outside a world's tick reaches that world as an input: inbound packets, chunk completions, and the results of offloaded work such as pathfinding, lighting or encoding.

  • No barrel files, and each package exports an explicit list of modules

    A barrel is a module that re-exports another module's symbols, whether or not it also declares its own.

  • A world exchanges only plain data with everything outside it

    Five rules keep a world's simulation separable from the code around it.

  • The change log is a world's history, complete and invertible

    The simulation's change log is the history of a world.

  • Vetoable actions run as intent, guard, compute and commit

    Every action that can be vetoed or modified runs in four stages.

  • Packet handlers share one shape in both directions, and serverbound handlers run in the input step

    Packet handlers register by packet name and session phase, in one shape defined in @jsprismarine/protocol that the server and the client package both use.

  • A tick is a fixed sequence of synchronous phases

    A world's tick runs these phases in this order.

  • Replication reads the change log after the tick

    Replication is a read-only stage that runs after a tick closes.

  • One lifecycle event bus replaces the legacy emitter

    The change log (ADR 0012) and the staged guards (ADR 0013) replace the simulation events.

  • A save is a snapshot of one tick boundary

    A save pass writes the authoritative state of one tick boundary of a level, called the save cut, for every dimension the level holds, and commits it as one atomic write.
