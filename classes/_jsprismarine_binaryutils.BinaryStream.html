    Class BinaryStream

    A high-performance binary stream for reading and writing binary data.

    Unlike Node.js native buffers which have fixed size, BinaryStream uses dynamic buffers that grow automatically during write operations. This eliminates the need for manual resizing or inefficient Buffer.concat() calls.

    Example: Reading data

    const stream = new BinaryStream(buffer);
    const value = stream.readInt();

    Example: Writing data

    const stream = new BinaryStream();
    stream.writeInt(42);
    stream.write(Buffer.from('Hello'));  // Buffer grows automatically
    const buffer = stream.getWriteBuffer();

    Example: Encoding many packets without allocating

    const stream = new BinaryStream(undefined, 0, 4096);
    for (const packet of queue) {
        stream.resetWrite();
        packet.encode(stream);
        offset = stream.copyInto(arena, offset);
    }

    copyOut

    • copyOut(): Buffer

      Returns the encoded bytes as an exactly-sized, standalone Buffer.

      Unlike getWriteBuffer the result does not alias this stream, so it survives resetWrite, and it does not pin a pool chunk: because Buffer.allocUnsafe is pool-backed (Buffer.poolSize is 64 KB on current Node), holding on to a handful of small slices from getWriteBuffer can keep megabytes alive.

    getWriteBuffer

    • getWriteBuffer(): Buffer

      Returns the encoded bytes as a view over this stream's internal buffer.

      The view is only valid until the next write: resetWrite, clear and reuse all rewind the cursor without reallocating, so a previously returned buffer is silently overwritten by the next packet. If you queue the result - a send queue, a resend window - use copyOut or copyInto instead.

      It also keeps the whole pooled 64 KB chunk it was carved from alive; retaining a scattered handful of small packets this way can pin megabytes.

      Returns Buffer

    reserve

    • reserve(capacity: number): this

      Grows the write buffer so that at least capacity bytes can be written without any further allocation, and returns this stream.

      Pre-sizing skips the 256 -> 512 -> 1024 ... growth ladder, each step of which copies the whole payload; a 3 KB packet starting from the 256-byte floor performs five allocations and memcpy's 1.25x its own size before it is done.

      Parameters

      • capacity: number

      Returns this

      • Defined in BinaryStream.ts:737

    resetWrite

    • resetWrite(): void

      Rewinds the write cursor while keeping the allocated capacity, so a long-lived encoder reaches a steady state where it never allocates again. This is the intended way to reuse a stream for many packets.

      Note the aliasing contract, which it shares with clear and reuse: any buffer previously handed out by getWriteBuffer is a view over this stream's memory and is invalidated by this call. Use copyOut or copyInto for output you intend to keep.

      Returns void

      • Defined in BinaryStream.ts:759
